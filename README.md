# FrostShield

Параметарско осигурување и јавен регистар на штети од доцни пролетни мразеви кај рано градинарство
(Струмица, Гевгелија, Валандово, Богданци).

Земјоделецот купува полиса за сезоната. Кога ќе има мраз во неговиот регион, оракулот го запишува на
блокчејн, а смарт-договорот сам ја пресметува штетата по култура и начин на производство и ја исплаќа.
Нема пријава, нема комисија за увид, нема чекање.

## Што е каде

| Дел | Технологија | Улога |
| --- | --- | --- |
| `contracts/` | Solidity 0.8.24, Hardhat, OpenZeppelin | Полиси, мразни настани, модел за штета, исплати. **Сè е на синџирот.** |
| `backend/` | Node.js, Express, ethers v6, node-cron | Оракул: чита часовни температури од Open-Meteo, пријавува мраз, автоматски ги активира исплатите. Прогноза за 7 дена. |
| `frontend/` | React 18, Vite, ethers v6, MetaMask | Преглед, купување полиса, мои полиси и исплати, регистар на мразеви, оракул/админ панел. |

Frontend-от чита **директно од синџирот** (не преку backend). Backend-от служи само како оракул и за временска прогноза.

### Што чува договорот

- **Полиси:** земјоделец, регион, култура, начин на производство, површина, сезона, покритие, платена премија, исплатено.
- **Мразни настани:** регион, датум, минимална температура, часови под 0 °C и под −2 °C, хеш на суровите часовни податоци.
- **Модел за штета:** критична температура и коефициенти по култура, заштитен фактор по начин на производство. Секоја промена е јавен настан.
- **Исплати:** која полиса, кој мраз, % штета, износ.

### Модел за штета (во договорот)

```
сурова штета = (критична т° − минимум) × bps по степен
             + часови под 0 °C × bps по час
             + часови под −2 °C × bps по час        (најмногу 100 %)
штета        = сурова штета × заштитен фактор (отворено 100 %, нисок тунел 60 %, пластеник 25 %)
исплата      = покритие × штета                     (вкупно најмногу покритието)
```

Почетните параметри се **некалибрирани примери**. Вистинските вредности се добиваат од ML моделот
во истражувањето (Random Forest / XGBoost на историски податоци) и се внесуваат преку `setCropParams`,
од панелот „Оракул“ → „Модел за штета“.

### Заштити

- Само адреса со `ORACLE_ROLE` пријавува мраз, само еднаш по регион и датум, и само за ден што веќе дошол.
- **Период на чекање (3 дена):** покриен е само мраз чиј датум е барем 3 дена по купувањето. Не може да се осигура градина што веќе измрзнала.
- Полиса се продава само ако базенот може да го покрие целото активно покритие.
- Админот може да повлече само вишок, никогаш резервираните средства.
- Исплатата секогаш оди на паричникот на земјоделецот, без разлика кој ја повикал.

## Стартување локално

Потребно: Node.js 18+ и MetaMask во прелистувачот.

### 1. Договор и локален блокчејн

```bash
cd contracts
npm install
npm test                 # 13 теста
npm run node             # локален блокчејн, остави го отворен
```

Во нов терминал:

```bash
cd contracts
npm run deploy:local     # деплој + 50 ETH во базенот; ги запишува адресата и ABI-то во backend/ и frontend/
```

> Ако компајлирањето не може да го симне компајлерот (нема пристап до binaries.soliditylang.org),
> пред командата стави `SOLC_OFFLINE=1`, на пр. `SOLC_OFFLINE=1 npm test`.

### 2. Backend (оракул)

```bash
cd backend
npm install
cp .env.example .env     # стандардните вредности работат локално
npm start                # http://localhost:4000
```

### 3. Frontend

```bash
cd frontend
npm install
cp .env.example .env
npm run dev              # http://localhost:5173
```

### 4. MetaMask

1. Додади мрежа: RPC `http://127.0.0.1:8545`, Chain ID `31337`, симбол `ETH` (апликацијата нуди и автоматско додавање).
2. Увези тест-сметка за земјоделец (Hardhat сметка #2):
   `0x5de4111afa1a4b94908f83103eb1f1706367c2e68ca870fc3fb9a804cdab365a`
3. За админ (менување на моделот) увези ја сметката #0:
   `0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80`

Овие клучеви се јавни и важат **само за локален Hardhat**. Никогаш не испраќај вистински средства на нив.

> Ако го рестартираш `npm run node`, MetaMask памети стар nonce. Во MetaMask: Settings → Advanced → Clear activity tab data.

## Демо за презентација (3 минути)

Договорот прифаќа мраз само за ден што веќе дошол. На локалната мрежа „Оракул“ → „Време на синџирот“
го поместува времето напред, па целата сезона може да се покаже за 3 минути.

1. **Оракул:** внеси API клуч `dev-oracle-key`, помести го времето на **10.02.2027** (почеток на сезоната).
2. **Купи полиса** (сметка #2): Струмица, домат, отворено, покритие 2 ETH. Десно се гледа колку би добил при различни мразеви.
3. **Оракул → Демо мраз:** Струмица, 15.03.2027, −2.5 °C, 5 часа под 0, 2 под −2. Договорот одбива: тој ден сè уште не дошол.
4. Помести го времето на **16.03.2027** и повтори го мразот. Тој е запишан и полисата е **автоматски исплатена**.
5. **Мои полиси:** 65.5 % штета → 1.31 ETH на паричникот на земјоделецот.
6. **Мразеви:** регистарот со хеш на податоците и матрицата на штета по култура. Пластеникот има 16 %, а отвореното 65 %.
7. Купи нова полиса сега (16.03) и покажи дека **вчерашниот мраз не ѝ се исплаќа**: не може да се осигура градина што веќе измрзнала.

За вистински податоци: „Оракул“ → „Вистински податоци“ → избери датум кога имало мраз (на пр. март 2024 или 2025)
→ „Провери температури“ → „Пријави на синџирот“. Backend-от ова го прави сам секој ден во 09:15 од февруари до април.

## Деплој на Polygon Amoy (testnet)

1. Направи паричник, земи тест POL од faucet (на пр. faucet.polygon.technology).
2. `contracts/.env`:
   ```
   AMOY_RPC_URL=https://rpc-amoy.polygon.technology
   DEPLOYER_PRIVATE_KEY=0x...      # паричник со тест POL
   ORACLE_ADDRESS=0x...            # адресата на оракулот (backend)
   SEED_POOL_ETH=1                 # колку POL да се стави во базенот
   ```
3. `npm run deploy:amoy`
4. `backend/.env`: `RPC_URL=https://rpc-amoy.polygon.technology`, `ORACLE_PRIVATE_KEY=` клучот на оракулот (треба малку POL за gas), смени `ORACLE_API_KEY`.
5. `frontend/.env`: `VITE_RPC_URL=https://rpc-amoy.polygon.technology`, `VITE_API_URL=` адресата на backend-от.

Трансакциите и договорот тогаш се гледаат на amoy.polygonscan.com, а линковите во апликацијата водат таму.

## API на backend-от

| Метод | Патека | Опис |
| --- | --- | --- |
| GET | `/api/health` | Состојба, блок, адреса на оракулот |
| GET | `/api/meta` | Региони, култури, адреса на договорот |
| GET | `/api/weather/:region?date=YYYY-MM-DD` | Часовни температури и показатели за мраз (без запишување) |
| GET | `/api/forecast/:region` | Прогноза за 7 дена со предупредување за мраз |
| GET | `/api/stats`, `/api/events`, `/api/policies?farmer=0x…` | Читање од синџирот |
| POST | `/api/oracle/report` `{region, date}` | Вистински податоци → мраз на синџирот → автоматски исплати |
| POST | `/api/oracle/simulate` `{region, date, minTemp, hoursBelow0, hoursBelowM2}` | Демо мраз |
| POST | `/api/oracle/auto-claim` `{eventId}` | Повторно активирање на исплатите за настан |
| POST | `/api/oracle/run-daily` `{date?}` | Дневната проверка веднаш |

POST повиците бараат заглавие `x-api-key: <ORACLE_API_KEY>`.

## Ограничувања (за прашања од жири / комисија)

- **Довербата во оракулот:** еден backend ги пријавува мразевите. Хешот на суровите податоци овозможува ревизија, но следниот чекор е повеќе независни извори (Chainlink Functions или неколку оракули со гласање).
- **Параметрите на моделот** се примери додека не се калибрираат со историски приноси.
- **Регион, а не парцела:** штетата се мери по регионална метеостаница; мразот во долини може да е посилен (базен ризик).
- **Покритието е во криптовалута** на тест-мрежа; за вистинска употреба би се користел стејблкоин (на пр. EURC) и лиценциран осигурител.
